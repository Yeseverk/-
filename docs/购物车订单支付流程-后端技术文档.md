## 2. 数据模型详解

### 2.1 购物车表 (tb_cart)

**实体类**: `com.cjc.pojo.TbCart`

```java
public class TbCart {
    private Long id;           // 主键ID（雪花算法）
    private Long userId;       // 用户ID
    private Long goodsId;      // 商品ID（SPU）
    private Long itemId;       // SKU ID（具体规格）
    private Integer num;       // 商品数量
    private Date createTime;   // 创建时间
    private Date updateTime;   // 更新时间
}
```

**核心字段说明**:

| 字段 | 类型 | 说明 | 重要程度 |
|------|------|------|----------|
| id | Long | 购物车记录主键，雪花算法生成 | ⭐⭐⭐ |
| userId | Long | 用户ID，区分不同用户的购物车 | ⭐⭐⭐ |
| goodsId | Long | 商品SPU ID，关联商品基本信息 | ⭐⭐⭐ |
| itemId | Long | SKU ID，决定具体规格和价格 | ⭐⭐⭐⭐ |
| num | Integer | 购买数量 | ⭐⭐⭐ |

**为什么需要 goodsId + itemId?**

```
商品(SPU)          SKU(规格组合)
┌───────────┐      ┌──────────────────────┐
│ iPhone 15 │──────│ itemId=1: 黑色 128GB │ 价格: 5999
│ goodsId=1 │      │ itemId=2: 黑色 256GB │ 价格: 6999
│           │      │ itemId=3: 白色 128GB │ 价格: 5999
└───────────┘      └──────────────────────┘

购物车记录: goodsId=1, itemId=2, num=1
含义: 用户要买一台 iPhone 15 黑色256GB版本，数量1台
```

```java
    private Long goodsId;      // 商品ID

```

**为什么需要价格快照?**

> 商品价格可能会变动，订单中的价格必须是下单时的价格，不能随商品后续调价而变化。
>
> `title` 和 `price` 字段存储的是下单时刻的快照数据，保证订单历史数据的一致性。

### 4.4 订单取消流程

**方法**: `OrderServiceImpl.cancel()`

```java
@Transactional
public void cancel(Long orderId, String userId) {
    // 1. 查询订单
    TbOrder order = orderMapper.selectByPrimaryKey(orderId);
    
    // 2. 权限校验：只能取消自己的订单
    if (!order.getUserId().equals(userId)) throw "无权操作";
    
    // 3. 状态校验：只有待付款状态可取消
    if (!OrderStatus.UNPAID.equals(order.getStatus())) 
        throw "只有未付款订单可以取消";
    
    // 4. 更新订单状态为已关闭
    order.setStatus(OrderStatus.CLOSED);
    order.setCloseTime(new Date());
    orderMapper.updateByPrimaryKeySelective(order);
    
    // 5. ★★★ 释放库存 ★★★
    releaseStock(orderId);
}

// 释放库存实现
private void releaseStock(Long orderId) {
    // 查询订单中的所有商品
    List<TbOrderItem> orderItems = orderItemMapper.selectByOrderId(orderId);
    
    // 逐个释放库存
    for (TbOrderItem orderItem : orderItems) {
        itemMapper.releaseStock(orderItem.getItemId(), orderItem.getNum());
    }
}
```

## 7. 关键技术细节

### 7.1 JavaScript Long精度丢失问题

**问题背景**:

JavaScript 的 `Number` 类型最大安全整数是 `2^53 - 1`（约9007万亿）。
本项目使用雪花算法生成的ID远超此范围，前端接收后会发生精度丢失。

```javascript
// 问题示例
后端返回: orderId = 1879234567890123456
前端接收: orderId = 1879234567890123000  // 精度丢失！

// 导致订单查询失败
GET /order/1879234567890123000  → 订单不存在
```

**解决方案**: 使用 Jackson 的 `@JsonSerialize` 注解将 Long 序列化为 String

```java
public class TbOrder {
    @JsonSerialize(using = ToStringSerializer.class)
    private Long orderId;  // 序列化为字符串 "1879234567890123456"
    
    // ...
}

public class TbOrderItem {
    @JsonSerialize(using = ToStringSerializer.class)
    private Long id;
    
    @JsonSerialize(using = ToStringSerializer.class)
    private Long orderId;
    
    @JsonSerialize(using = ToStringSerializer.class)
    private Long itemId;
    
    @JsonSerialize(using = ToStringSerializer.class)
    private Long goodsId;
}
```

**Controller层也需处理**:

```java
@PostMapping("/create")
public Result create(OrderCreateDto dto, HttpServletRequest request) {
    Long orderId = orderService.create(dto, getUserId(request));
    // 返回时转为字符串
    return Result.success(orderId.toString());
}
```

### 7.2 乐观锁扣减库存

**并发场景问题**:

```
时刻T1: 用户A查询库存 = 10
时刻T2: 用户B查询库存 = 10
时刻T3: 用户A下单5件 → 扣减库存
时刻T4: 用户B下单5件 → 扣减库存
结果:   库存 = 0，但用户A+B共买了10件
问题:   如果实际库存只有5件，会导致超卖！
```

**乐观锁解决方案**:

```sql
-- 扣减库存SQL（TbItemMapper.xml）
UPDATE tb_item
SET stock_count = stock_count - #{num}
WHERE id = #{itemId}
  AND stock_count >= #{num}  -- 条件：当前库存必须≥购买数量

-- 如果条件不满足，UPDATE返回0行，表示扣减失败
```

```java
// Java代码
int rows = itemMapper.deductStock(itemId, num);
if (rows == 0) {
    throw new BusinessException("库存不足，下单失败");
}
```

**为什么叫"乐观锁"?**

> 不使用显式的锁（如 SELECT FOR UPDATE），而是通过 SQL WHERE 条件实现并发控制。
> 
> 假设大部分情况下不会冲突，只在更新时检查条件。如果失败，说明有冲突，直接报错。

### 7.3 雪花算法订单号生成

**IdWorker 工作原理**:

```
雪花算法ID结构（64位）:
┌────────────────────────────────────────────────────────────────┐
│ 0 │ 41位时间戳 │ 10位机器ID │ 12位序列号                        │
└────────────────────────────────────────────────────────────────┘

特点:
1. 全局唯一：不同机器、不同时刻生成的ID不会重复
2. 时间有序：ID按时间递增，便于排序和索引
3. 高性能：单机每秒可生成400万+ ID
4. 无需数据库：不依赖数据库自增序列

生成示例: 1879234567890123456
```

```java
@Autowired
private IdWorker idWorker;

// 生成订单号
Long orderId = idWorker.nextId();

// 生成订单商品ID
Long orderItemId = idWorker.nextId();
```

### 7.4 事务原子性保证

**为什么需要 @Transactional?**

下单过程涉及多个数据库操作：
1. 扣减库存
2. 创建订单主表
3. 创建订单商品明细（多条）
4. 清除购物车记录

如果任何一步失败，必须全部回滚，否则会出现数据不一致。

```java
@Transactional
public Long create(OrderCreateDto dto, String userId) {
    // 1. 扣减库存（可能失败）
    // 2. 创建订单（可能失败）
    // 3. 清除购物车（可能失败）
    
    // 任意失败 → 自动回滚所有操作
    // 全部成功 → 提交事务
}
```

**事务失败回滚示例**:

```
尝试下单:
├── 扣减库存成功（stock: 10 → 5）
├── 创建订单成功
├── 创建订单商品成功
└── 清除购物车失败（数据库异常）

结果: 全部回滚
├── 库存恢复（stock: 10）
├── 订单删除
├── 订单商品删除
└── 购物车不变

用户收到错误: "下单失败，请重试"
```

### 7.5 SKU查询多重兜底策略

订单服务中，SKU查询采用多重兜底策略确保能找到有效SKU：

```java
TbItem item = null;

// 策略1: 优先使用购物车中保存的itemId
if (cart.getItemId() != null) {
    item = itemMapper.selectByPrimaryKey(cart.getItemId());
}

// 策略2: 尝试商品的defaultItemId
if (item == null && goods.getDefaultItemId() != null) {
    item = itemMapper.selectByPrimaryKey(goods.getDefaultItemId());
}

// 策略3: 查询商品的默认SKU记录
if (item == null) {
    item = itemMapper.selectDefaultItemByGoodsId(cart.getGoodsId());
}

// 策略4: 查询任意一个SKU作为兜底
if (item == null) {
    item = itemMapper.selectFirstItemByGoodsId(cart.getGoodsId());
}

// 最终兜底失败
if (item == null) {
    throw new BusinessException("商品暂无可用SKU");
}
```
